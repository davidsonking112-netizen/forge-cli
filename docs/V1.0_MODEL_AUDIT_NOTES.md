# Forge CLI v1.0 model-audit notes

The built-in model catalog was fetched on 2026-08-26 from the configured OpenAI-compatible `/models` endpoint described by the Manus built-in model guidance. The catalog reported current model IDs and pricing/capabilities; this note intentionally does not copy pricing into product code because the catalog is dynamic.

The first independent review run completed with `gemini-3-flash-preview` and identified possible areas requiring verification, including ACP input buffering, path-validation race considerations, and ACP memory bounds. Its response was truncated by the provider output limit, so those observations are hypotheses requiring local confirmation, not accepted defects.

A second three-model run was attempted with `gpt-5`, `claude-sonnet-4-6`, and `gemini-3-flash-preview`, but the proxy returned no choices because the requested review context exceeded the currently available execution capacity. No claim is made that the whole application is bug-free or zero-day-free. v1.0 verification therefore combines the independent model observation, local source review, deterministic tests, dependency audit, and targeted bounded-input testing; additional independent model review remains a recommended release-readiness item when provider capacity is available.

The audit source was the complete tracked Forge snapshot assembled from TypeScript, Python, protocol, tests, manifests, and documentation, with generated artifacts and the long historical optimization brief excluded. External evidence:

- Built-in catalog endpoint: `$OPENAI_API_BASE/models` (environment-injected; current catalog source at audit time).
- Daytona API reference used by v0.99: https://www.daytona.io/docs/en/tools/api/
- Daytona sandbox lifecycle documentation: https://www.daytona.io/docs/en/sandboxes/
  Official provider documentation verification: Google’s OpenAI-compatibility page states that Gemini can use OpenAI libraries with `https://generativelanguage.googleapis.com/v1beta/openai/` and a Gemini API key obtained from Google AI Studio. Source: https://ai.google.dev/gemini-api/docs/openai.
  Official provider documentation verification: OpenRouter documents an OpenAI-compatible `/api/v1/chat/completions` endpoint at `https://openrouter.ai/api/v1`, Bearer authorization, and optional `HTTP-Referer`/title attribution headers. Source: https://openrouter.ai/docs/quickstart.
  Official provider documentation verification: Groq documents OpenAI client compatibility at `https://api.groq.com/openai/v1` with a Groq API key. Groq also documents compatibility limits, including unsupported fields such as `logprobs`, `logit_bias`, and `top_logprobs`, so Forge’s minimal chat-completions payload avoids those fields. Source: https://console.groq.com/docs/openai.
  Official provider documentation verification: xAI states that its Inference REST API is fully compatible with the OpenAI REST API, uses `https://api.x.ai` as the base, and requires `Authorization: Bearer <xAI API key>`. Forge uses the compatible `/v1/chat/completions` path. Source: https://docs.x.ai/developers/rest-api-reference/inference.
