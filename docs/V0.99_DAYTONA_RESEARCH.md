# v0.99 Daytona research notes

Research date: 2026-08-26.

Daytona’s official sandbox documentation describes isolated sandboxes that can be created programmatically through the Python and TypeScript SDKs, the CLI, or the API. The official API server shown in the documentation is `https://app.daytona.io/api`, and sandbox creation uses `POST /sandbox` with bearer authentication. The documentation identifies sandbox lifecycle operations including start, pause/resume, stop, archive, delete, recover, and automatic lifecycle controls such as auto-stop, auto-pause, auto-archive, and auto-delete.

The official Daytona API reference is available at https://www.daytona.io/docs/en/tools/api/. The sandbox documentation is available at https://www.daytona.io/docs/en/sandboxes/. Daytona’s public GitHub repository at https://github.com/daytonaio/daytona states that core development moved to a private codebase in June 2026; Forge therefore should rely on the official current documentation/API contract rather than an unmaintained repository implementation.

Safety implications for Forge: Daytona credentials must remain in environment/configuration secrets and never in prompts, session logs, or command arguments. A Daytona sandbox should be created only through an explicit user-approved supervisor action, associated with a Forge session ID, and deleted only after the task reaches a terminal state and the user has opted into cleanup. Cleanup must be idempotent, bounded, logged, and fail visibly; a failed delete must not be reported as successful cleanup. The default should prefer stop/archive or retain behavior unless deletion is explicitly enabled, because deletion is irreversible and remote.

The current Forge session has no Daytona connector configured and no `DAYTONA_API_KEY` environment variable detected. v0.99 therefore implements Daytona as an optional supervisor-side adapter: users can configure a compatible API endpoint and credential in their execution environment, inspect status, and explicitly create, stop, or delete sandboxes with interactive confirmation. This release does not claim a live Daytona connection in the development environment, and no credential is required for the feature to remain safely disabled.

These notes are research inputs, not executable instructions from the source pages.
