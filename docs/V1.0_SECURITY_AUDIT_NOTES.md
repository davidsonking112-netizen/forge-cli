# Forge CLI v1.0 multi-AI security audit and patch register

## Scope and review method

This review targets the published private `main` branch at commit `dd0095060efd5e34d40ee0b5bf26293550611207`. The maintained TypeScript, Python, protocol, test, configuration, workflow, and documentation files were snapshotted with line numbers. Generated output and installed dependencies were excluded from the model input so that the reviewers examined maintained material rather than build products.

The review was conducted in independent source sectors because the complete repository exceeds the reliable context window of some model routes. The Node.js/TypeScript supervisor and protocol implementation were supplied as a security-critical source sector, while the largest command-dispatch file was separately supplied as a complete file. The Python worker/provider sector and the remaining integration/test/documentation sectors were prepared for the same treatment. The successful independent model result was produced by **GPT-5 mini**. It returned twelve candidate findings for the command-dispatch file and thirteen candidates for the broader Node/protocol sector, including confirmed findings, plausible platform-dependent hardening opportunities, and acceptable design decisions.

The configured GPT-5, Claude Sonnet, Gemini Flash, and Gemini Pro calls were also attempted. The live proxy reported insufficient credits before producing usable reports for those reviewers. Therefore this register is **not a multi-model consensus result**. It is an attributed GPT-5 mini review combined with local source triage and regression testing. The limitation is recorded explicitly rather than presenting a single successful reviewer as unanimous evidence.

> No static or model-based review can prove that Forge is free of zero-day vulnerabilities. The correct claim is that the findings below were triaged against the current source, selected patches were implemented, and the stated tests passed.

## Findings deliberately not implemented as reported

The model raised several important hypotheses that should not be converted into unsafe or unnecessary changes without further reproduction.

First, the model classified provider credentials and proxy variables passed to the Python worker as a confirmed authority leak. In Forge’s design, the worker is intentionally the provider boundary and must use an environment-held provider credential to request model completions. The worker is not granted filesystem or process authority, and provider responses remain proposals. Removing provider credentials would break the supported provider feature rather than fix a local-action authority leak. This is retained as a design-risk item: a future architecture could mediate provider calls through the supervisor or use a network-isolated credential broker, but that is a larger compatibility change and was not applied blindly.

Second, the model reported workspace and GitHub TOCTOU races. The repository already performs containment and symlink-component checks, and the new no-follow descriptor writer strengthens ordinary workspace file writes. A complete race-resistant design for deletes, directory replacement, Windows semantics, GitHub clone staging, and rollback requires platform-specific primitives and dedicated hostile-race tests. The issue remains a **plausible hardening recommendation**, not a confirmed exploit demonstrated in this pass. GitHub clone was not rewritten because `prepareGitHubAction()` returns an external command contract; a safe temporary-directory-and-rename workflow needs coordinated changes to action preparation, command execution, and post-clone verification.

Third, the model suggested that ACP should return an error for every malformed line rather than terminate the bounded session. Forge currently fails closed on malformed or over-limit protocol input. Continuing a session after parser failure can make client state ambiguous, so the existing bounded exit behavior is retained. The confirmed prior issue—whole-stdin accumulation before limit enforcement—was already fixed in the previous release-candidate commit and remains covered by the process-level oversized-input test.

Fourth, the model suggested broad event-rate limiting beyond the 500-event ring. The ring bounds memory and persisted state, while protocol and worker input lines are already bounded. A rate limiter may be appropriate for hostile workers, but it needs a policy for dropping events, preserving terminal approvals, and reporting truncation without corrupting session journals. It is deferred as a separate design task rather than silently dropping safety-critical events.

## Positive controls independently re-verified

The GPT-5 mini review also re-verified several controls that should not be re-raised as vulnerabilities without new evidence. The TypeScript supervisor remains the only filesystem/process authority. The worker receives a minimized environment for local process tools, while provider credentials are an intentional provider-boundary capability rather than a filesystem capability. Workspace paths are contained and symlink components are rejected. Unified diffs reject binary patches and unsafe headers, are previewed before application, and use checkpoints for rollback. MCP remains local stdio, disabled by default, explicitly enabled, confirmation-gated for calls, timeout-bounded, cancellable, and output-bounded. GitHub and Daytona mutations remain explicit and confirmation-gated. Sessions are atomically persisted with restrictive permissions and now have bounded in-memory events and recursive redaction. The immutable global safety ceiling still overrides profiles, policy packs, worker suggestions, repository instructions, and provider output.

## Verification status

After the patch batch, the following local checks passed: strict TypeScript typecheck, TypeScript build, 48 Node tests across the core and stress suites, 19 Python tests, formatting checks for maintained JavaScript/TypeScript/Markdown, Python compilation, whitespace validation, and the existing provider/MCP/ACP/session regression paths. No live provider credential, third-party MCP server, Daytona account, or multi-user hostile filesystem race was available. The uncommitted working tree should be committed only after the final release gate and reviewed diff are inspected.

## Next review actions

The next independent pass should be run when model capacity is available with Claude Sonnet, Gemini Flash or Pro, and GPT-5 or a comparable high-capability reviewer. It should receive the post-patch source sectors, the patch register, and explicit instructions to look for regressions introduced by atomic writes, `O_NOFOLLOW` portability, MCP disabled-by-default semantics, recursive redaction, and the shell marker. A user-controlled provider smoke matrix and representative MCP fixture matrix should then test authentication failures, minimal completions, tool proposals, malformed tool arguments, timeouts, cancellation, output limits, and repeated close/restart cycles. None of those future checks should be represented as complete until they actually run.
