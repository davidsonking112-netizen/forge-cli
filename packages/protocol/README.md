Forge protocol v1 is a line-oriented JSON event stream. One complete JSON object is written per line. The Node.js supervisor and Python worker use the same envelope fields: `protocol`, `id`, `sessionId`, `type`, and `timestamp`.

Standard output is reserved for protocol messages. Standard error is reserved for diagnostics and must never be parsed as an event. Every tool proposal has a named tool, risk classification, JSON arguments, and reason. Every tool result reports approval, success, duration, and either bounded output or a structured error.

The v0.99 contract, retained in the v1.0 candidate, includes first-class `agent.delegation` events for bounded specialist activity and optional session autonomy profiles. It adds bounded `agent.scratchpad` events containing short task, inspection, current-step, change, verification, and next-action entries, plus `agent.checklist` events containing item IDs, labels, user-facing expectations, bounded status, and optional notes. Checklist and scratchpad state are planning metadata only and never authorize a tool. Delegation events may include bounded non-secret budget telemetry for profile, planned/used roles and turns, context/output character counts, and skipped-role reasons. `agent.repair` records a bounded attempt number, alternate or deep-thinking strategy, outcome, and reason; it cannot authorize retries or bypass supervisor approval. Supervisor-owned `agent.state` events expose the enforced phase (`intake` through `summarize`), entry conditions, required artifact, exit condition, failure transition, current step, and bounded provider/tool/repair budgets. These events are telemetry and persisted evidence; neither the provider nor a model-written status can advance or complete a session. `agent.plan` may additionally propose a dependency graph whose steps declare expected files, dependencies, risks, tests, and postconditions. Forge normalizes that proposal into `agent.graph`, assigns deterministic stable step IDs, validates contracts and cycles, and reports each step as `pending`, `ready`, `active`, `completed`, `blocked`, or `failed`. The model cannot select a blocked step: mutation and verification proposals are rejected until their graph step is ready and every dependency is supervisor-verified complete.
`session.start` may include a bounded workspace fingerprint and a recovery assessment identifying `continue`, `re-plan`, or `manual-intervention` without authorizing replay. Unified-diff application is represented by the reversible-write `workspace.apply_unified_diff` tool and remains supervisor approval-gated; read-only previews describe a selected file-level change set and deterministic digest, while application reuses preflight, remains stale-validated, checkpointed, and all-or-rollback. Approval-session decisions carry an ephemeral exact-argument scope and expiry, with bounded path metadata, rather than blanket authorization.

The canonical event schema is [`schema.json`](./schema.json). The TypeScript implementation is in [`src/index.ts`](./src/index.ts). MCP and ACP adapters map their wire-level events to these internal boundaries rather than coupling the supervisor to a vendor-specific message format. Local MCP requests support cancellation and categorized lifecycle errors; ACP responses preserve request correlation, stream input under aggregate byte and request-count caps, and categorize parse, request, parameter, and unsupported-event failures.
The shared parser rejects unknown event types, unknown tools, invalid enums, NUL bytes, and oversized fields before they enter supervisor state. The supervisor intercepts mutation proposals until a plan artifact exists and the dependency graph authorizes the active step, records state transitions around tool outcomes, and rejects a completed mutation claim until it has observed a successful change with changed-file evidence plus distinct targeted and broad verification results. A graph with an invalid contract, cycle, or incomplete prerequisite fails closed. Completion checks are evidence-based: the supervisor’s command result supplies status, exit code, duration, bounded output, finish time, truncation state, workspace fingerprint, command digest, and Forge tool version. Persisted session records additionally retain a bounded step journal, checklist, scratchpad, recovery assessment, and verification evidence digest; resume revalidates the fingerprint and never replays a mutation automatically. The CLI’s `forge audit` command provides a redacted projection of persisted lifecycle events for post-run safety review. Context selection reports bounded pruning statistics, and the provider worker may compact older conversation messages into a deterministic summary while retaining hard message and turn limits.
GitHub status, login, clone, private repository creation, and push are explicit CLI-supervisor workflows, not worker-authorized protocol capabilities. Daytona status, sandbox creation, stop, and delete are likewise supervisor-only optional CLI workflows; the API key is never a protocol field or worker capability, and cleanup is opt-in and confirmation-gated.
